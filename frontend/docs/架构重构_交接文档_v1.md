> **文档性质**：用户体验架构师 → 前端工程师的逐文件改造 spec。

## 0. 一句话说清这次重构

把产品从「**识别 → 摆放 → 比价下单**」的工具链，重构为「**摆放 → AI 点评 → 选改造方向 → 出方案/荐单品/直接改 → 分享传播**」的**决策 + 传播闭环**。

**核心变化**：
1. **比价/下单彻底删除**（order 页停用，主链路移除）。
2. **「改方向」升为第一阶梯**：进入空间摆完后，先让用户选"要往哪个方向改"（养宠/养娃/动线/风水/配色…），选定后才展开三种深化动作。
3. **摆放页（place）成为唯一主战场**，承载：3D 画布 + 参数区 + AI 点评卡 + 方向选择器 + 方向内三动作 + 顶部邀请/分享 + 养宠彩蛋。
4. **画布为手机竖屏原生布局**：方形画布置顶 + 画布右下角参数入口 + 画布下方家具资产库（**不照搬酷家乐 PC 三栏**）。**参数区字段必须保留**（后端要求），酷家乐参考图仅用于字段对齐。**3D 由后端实现，前端只留渲染插槽接口**（§6.6）。
5. **「试改」态**：动作③一键套用是临时预览，用户点「保留」才落库，可一键「还原」。
6. **配色全量替换**（§10）：页面底色改为**纯白**，其余用 Firmament Blue（文字/深色区）/ Atomic Orange（CTA/选中）/ Burgundy（警示/删除）三色，重写 `tokens.scss` 色板。
7. **资产库抽取动效改为平铺横滑**（§11）：空间资产库 / 家具资产库放弃「书架垂直抽取（3D 立起）」，改为平铺卡片横向滑动，选中态用轻量放大/浮起。

## 1. 用户主链路（最终版）

```
抖音刷到暂停 →（截图/挂车链接）抽帧生成 3D 家具模型 → 进入小程序
  → 选空间【扫描 / 上传户型图 / 选模板空间】
  → 进入摆放页：从家具库拖家具进空间、调方位看 match
  → 首次摆放完成 → AI 点评卡【自动弹一次】
  → 点评收起 → 方向选择器上位（第一阶梯）
  → 选一个方向（如「养宠」）
  → 展开该方向的三动作：① 出方案(文本) ② 荐单品(直达抖音) ③ 直接改空间(试改→保留/还原)
  → 改完点评刷新 → 可返回换方向，循环
  → 顶部随时【邀请朋友】/【分享设计图】
  → （彩蛋）画布右下角【养只宠物】
```

**已删除**：比价、下单、order 页入口。推荐单品的唯一变现出口 = **直达抖音商城外跳**。

## 3. 摆放页（place）详细布局 — 手机竖屏原生布局

> **重要修正**：酷家乐三栏（左素材/中画布/右参数）是 **PC 编辑器布局，不适配手机**。本项目为竖屏小程序，改为**纵向单列**：上方方形画布 → 画布右下角挂参数入口 → 画布下方为家具资产库 → 再下为点评/方向/三动作。参考图仅用于**参数区字段对齐**，布局不照搬。
>
> **3D 说明**：后端同学会上真 3D。**前端本轮只负责留接口和 UI 壳，不实现渲染**。SpaceCanvas 定义为一个"渲染容器"：内部预留 `render slot`，本轮用现有 2D 俯视贴图占位，后端 3D 引擎就位后替换容器内部实现，外围布局/交互契约不变。

### 3.2 SpaceCanvas（方形画布，置顶）

- **形状与尺寸**：正方形，`width = 100%（屏宽）`，`height = width`（用 `aspect-ratio: 1/1`）。这是全页主视觉，占首屏上半部。
- **渲染容器（关键）**：SpaceCanvas 是一个**渲染插槽容器**，本轮内部塞现有 2D 俯视贴图拖拽（`place` 已有的 touch 拖拽/吸附/震动**全部保留**）。**后端 3D 引擎就位后，只替换容器内部渲染实现**，SpaceCanvas 对外的 props/事件契约（见 §6.6）保持不变——这就是"留接口"的落点。
- **画布内浮标（绝对定位，不占文档流）**：
  - **左上**：`2D | 3D` 视图切换（本轮 3D 为占位/禁用态，点击提示"3D 即将上线"）。
  - **左下**：`🐾 养宠`彩蛋浮标（§3.7）。
  - **右下**：`⚙ 参数`小块——**这是参数区的唯一入口**（你指定的位置）。点击弹出参数修改层（§3.3）。
- **家具库不在画布内**：画布只负责"空间 + 已放置家具"，家具资产库独立在画布下方（§3.2b）。

### 3.2b FurnitureLibrary（家具资产库，画布正下方）

- 位置：紧贴画布下方的一条横向滑动区（不是侧边抽屉）。
- 内容：公共/我的 tab + 品类筛选 + 单品卡，复用现有 `CoverShelf`/`CoverImage` 视觉。
- 交互：**长按单品 → 拖入上方画布**落位；或点单品 → 出现在画布中央待拖动（沿用现有 recognize→place 的落位逻辑）。
- 触摸适配沿用上轮成果（`:active` 按压 / `touch-action` / haptics）。

### 3.3 ParamPanel（参数修改层，点画布右下「⚙参数」弹出）

- **触发**：点画布右下角 `⚙ 参数`小块 → 从底部升起半屏弹层（画布压暗，`liquid-glass` 遮罩）。
- **字段严格对齐参考图**（后端要求保留，本轮 mock 默认值渲染）：
  - **楼层属性**：`参数设置` / `空间风格` 两 tab（本轮先做"参数设置"tab，"空间风格"留壳）。
  - **基础参数**：套内使用面积（m²）、层高（mm，默认 2800）、楼板厚度（mm，默认 120）。
  - **户型不透明度**：墙体滑块（默认 80%）、楼板滑块（默认 50%）。
  - **底圈显示**：开关（默认开）。
  - **当前楼层**：楼层选择（1F…）+ 新建上层/下层（本轮单层，多楼层留壳）。
- **底部**：`完成`按钮，收起弹层、参数写入 `RoomParams`（§6.2）。
- **字段读写走 §6.2 契约**，本轮前端渲染 UI + 本地 mock 值，后端接 `GET/PATCH /rooms/{id}/params` 时零改动。

> **注意**：参数区不再是"右缘常驻侧栏"，而是"画布右下角入口 → 点开弹层"，符合手机竖屏。

- **点评卡收起后，方向选择器上移成为屏幕视觉主角**（你已确认"点评收起后方向上位"）。实现：点评从半屏 sheet 收为一条细条时，DirectionPicker 用 `fade-rise` 动画上移填补空间。

### 3.6 DirectionActions（方向内三动作 · 第二阶梯）

选中方向后原地展开：
- 顶部条 **`当前方向：养宠 ▾`** —— 点它可**换方向**（回到 Picker 选择态，不锁死）。
- 三张动作卡（顺序固定）：
  1. **① 出方案** → 打开 suggest（带 `direction`），出该方向文本 solution。卡内挂「看推荐 ›」快捷入口。
  2. **② 荐单品** → 打开 recommend（带 `direction`），出对症单品列表。

## 4. 「试改」态规格（你已确认要做）

**目的**：动作③一键套用布局会覆盖用户手摆位置，必须可逆，否则用户手摆半天被 AI 冲掉会崩溃。

**状态机**：
```
normal ──点「直接改空间」──▶ preview（试改态）
preview ──点「保留」──▶ committed（落库，回 normal）
preview ──点「还原」/切方向/退出──▶ normal（丢弃预览）
```

**规则**：
- 进入 `preview`：把当前 `placements` 快照存入 `previewBackup`（内存，不落库），再套用 AI 布局到画布**仅视觉呈现**。
- 画布顶部出现浮条：**「试改预览中 — [保留改动] [还原]」**（醒目，用 accent 色）。
- `preview` 期间点评卡显示"改后预估评分"（可与改前对比）。
- 点**「保留」**：预览布局写入 store + Storage（落库），清空 backup，点评刷新为正式分。
- 点**「还原」**或切换方向或退出页面：用 `previewBackup` 恢复，丢弃预览。
- **同一时刻只允许一个试改预览**，再次点③会提示"当前有未保存的试改，先保留或还原"。

### 6.6 SpaceCanvas 渲染插槽契约（3D 留接口的核心）★

后端将上真 3D。前端本轮**不实现渲染**，只定义 SpaceCanvas 的对外契约，让 3D 引擎日后"插进来"即可，外围布局/交互零改动：

```ts
export interface SpaceCanvasProps {
  roomId: ID
  placements: Placement[]              // 已放置家具（含坐标/旋转/缩放）
  params: RoomParams                   // 参数区数据（层高/不透明度等，透传给渲染器）
  viewMode: '2d' | '3d'                // 视图模式；本轮 3d 为占位禁用
  editPhase: 'normal' | 'preview'      // 试改态，preview 时渲染预览布局
  onPlacementChange: (p: Placement) => void   // 拖拽/落位回调 → 落库
  onPlacementSelect?: (id: ID) => void
  onDropFurniture?: (furnitureId: ID, at: {x:number;y:number}) => void // 从家具库拖入
  renderer?: 'canvas2d' | 'three'      // 渲染实现开关；本轮固定 'canvas2d'
}
```

- **本轮实现**：`renderer='canvas2d'`，内部 = 现有 2D 俯视贴图 + touch 拖拽/吸附/震动。
- **3D 接入方式**：后端/引擎方提供 `renderer='three'` 的内部实现，**只替换 SpaceCanvas 内部渲染层**；`SpaceCanvasProps`（尤其 placements/params/回调）保持不变。
- **约定**：所有页面/组件**不得**直接操作画布 DOM 或坐标系，一律通过上述 props/回调，保证 2D→3D 替换时上层无感。

## 10. 配色全量替换（重写 tokens.scss）★ 新增需求

**决策**：放弃原莫兰蒂色板，改用「**纯白底 + 三色**」共四色（2026-07-24 修订：三色由 Blue/Yellow/Light Blue 取代原 Firmament Blue/Atomic Orange/Burgundy）：

| 名称 | HEX | RGB | 语义角色 |
|---|---|---|---|
| White | `#FFFFFF` | 255 255 255 | **页面底色**（bg-primary，大面积留白，主背景） |
| Blue | `#05256D` | 5 37 109 | **标题/正文文字 + 深色区底**（text-primary，白底对比极高） |
| Yellow | `#FFDE4E` | 255 222 78 | **主 CTA / 选中态 / 高亮**（accent，全站唯一行动色；黄底上一律深蓝字，勿用白字） |
| Light Blue | `#81C4FB` | 129 196 251 | **辅助色**：信息态 / 次级面 / 点缀 |

### 10.1 tokens.scss 映射（逐变量覆盖）
```scss
// 背景
--color-bg-primary:    #FFFFFF;   // 页面纯白底（原 #F5ECD2 废弃）
--color-bg-secondary:  #F5F6F9;   // 极浅冷灰白，卡片/次级面（深蓝 3% 派生）
// 主色 / 强调
--color-primary:       #0E1733;   // Firmament Blue，深色基调（导航/深色区/文字）
--color-surface-dark:      #0E1733;   // 深色区底(默认)，配白字，见 §10.4 方案A

--color-error:         #6D1E21;   // 错误/删除 = Burgundy
// 高亮点睛
--color-highlight:     #F98603;   // Atomic Orange，高分/角标/选中
```

### 10.2 应用规则（防止色彩滥用）
- **白底为绝对主背景**，其余三色做前景/点缀，任一色块（除白）面积不超过屏幕 40%。
- **文字**：白底上一律用 **Firmament Blue #0E1733**（近黑深蓝，对比度极高、比纯黑柔和）；深蓝色块上用白字，白字上的强调用橙。
- **CTA/选中/高亮**：一律 **Atomic Orange**，是全站唯一"行动色"，保持稀缺；橙块上文字用深蓝 `#0E1733`（橙+深蓝对比清晰，勿用白字，白字在橙上对比不足）。
- **Burgundy 克制使用**：只用于**警示/删除/危险**等负向操作，与橙形成冷暖区隔，避免两个暖色（橙+酒红）大面积并置抢戏。
- **深色区**（点评卡、深色 Hero）用 Firmament Blue 打底 + 白字 + 橙色数字/强调。
- **浮雕体系调整**：原莫兰蒂浮雕阴影在纯白底上要重新调，`effects.scss` 的 `--shadow-emboss` 系列改为基于 `#0E1733` 低透明的冷色投影，避免脏黄/脏红。

### 10.3 影响面
- `src/styles/tokens.scss`：全量改色值（**唯一改色入口**，页面/组件不动，因全走变量）。
- `src/styles/effects.scss`：浮雕/liquid-glass 阴影底色适配白底（冷蓝投影）。
- `src/app.config.ts`：`navigationBarBackgroundColor` / `backgroundColor` 改 `#FFFFFF`；tabBar `selectedColor` 改 `#F98603`、`color` 改 `#0E1733`（未选深蓝、选中橙）、`backgroundColor` 改 `#FFFFFF`（小程序原生配置只能写色值，与 token 同步）。
- **验收**：全站无残留旧色（#F5ECD2/#962D49 等），grep 确认；WCAG AA 对比度：深蓝文字 on 白 ✓（≈15:1）；深蓝文字 on 橙 ✓（≈5:1）；**橙块勿配白字**（≈1.9:1 不达标）；白字 on 深蓝 ✓；白字 on Burgundy ✓（≈8.7:1）。

### 10.4 深色区底色的两种可选方案（前端可择一/混用）

深色区（点评卡、深色 Hero、浮层、强调块）的**底色**有两个合规选项，工程师按场景择一，也可两者分场景混用：

| 方案 | 底色 | 文字 | 强调/数字 | 对比度 | 适用场景建议 |
|---|---|---|---|---|---|
| A（默认） | Firmament Blue `#0E1733` | 白 `#FFFFFF` | Atomic Orange `#F98603` | 白字 ≈15:1 | 冷静、信息型深色区（点评卡、参数区标题条） |
| B（可选） | Burgundy `#6D1E21` | 白 `#FFFFFF` | Atomic Orange `#F98603` | 白字 ≈8.7:1 | 需要温度/情绪的深色区（分享海报、强调浮层、彩蛋卡） |

- 两方案**均达 WCAG AA**，白字都安全；橙色数字/强调在两种底上都清晰。
- **约定**：底色走语义变量，不要硬编码——新增 `--color-surface-dark`（默认 `#0E1733`）；若某区要用 Burgundy 底，用 `--color-surface-dark-warm`（`#6D1E21`）。两者都提供，页面按场景引用，保证全局可一键切换基调。
- **一致性提醒**：同一类组件（如所有点评卡）应统一用 A 或 B，不要一张蓝一张红；建议 A 做常规深色区、B 只留给"分享/彩蛋"等需要情绪的少数场景，避免深色区风格发散。

## 11. 资产库抽取动效：垂直抽取 → 平铺横滑 ★ 新增需求

**决策**：空间资产库 / 家具资产库（现 `CoverShelf` 组件的「书架 3D 垂直抽取」效果）**取消**，改为**平铺卡片 + 横向滑动**。

### 11.1 改动点（`src/components/CoverShelf/` 或新组件）
- **移除**：`rotateY(-28deg)` 书脊倾斜、`translateZ` 抽出、`perspective`、书脊 `::before` 阴影、相邻让位 `is-shift-left/right`、滚动居中自动抽出（上轮 P0-3 的 rect 实测逻辑一并下线）、首卡脉冲。

### 11.2 保留/可自行完善的部分
