## 1. 相对原交接，多了什么

原 MVP：

```text
视频/单帧 → 检测打标 → 选物 → 参考图 → Image-to-3D → GLB
```

`cutting` 上额外两条产品能力：

```text
A. 空间可行性 / 布局 Agent
   场景 + 候选家具位姿
     → 几何检查（碰撞/净空/可达/fit）
     → 可选 LLM 布局模块 / 全屋布局 / 场景化建议（养老·育婴·养宠·风水）

B. 视觉商品检索（离线 IKEA + CLIP）
   crop / 整图
     → OpenCLIP + FAISS（本地索引）
     → TopK 宜家相似商品（缓存 API 或实时 clip-search）
```

另有一套 **mock 商品识别/推荐**（`/api/product/*`，本地 `catalog.json`），代码在仓库里，但 **当前 `main.py` 未挂载**（见 §8）。

房间扫描 `POST /api/room/scan` **仍是 mock**，与原说明一致。

## 4. 功能脉络 A：空间布局

### 几何层（无 LLM 也可跑）

`run_spatial_check(candidate, scene)`：

- 碰撞、净空、门/通道可达、尺寸 fit 等  
- 规则数据：`layout_reasoning/rules/clearance_rules.json`  
- 产出 `overallStatus` + `checks` + 基础 `feedback`

### Agent 层（可选）

依赖 `.env`：

| 变量 | 说明 |
|------|------|
| `SPATIAL_AGENT_PROVIDER` | `ark`（走文本模型）/ `mock` |
| `ARK_API_KEY` / `ARK_BASE_URL` / `ARK_TEXT_MODEL` | 布局文案；本机案例曾用 Paratera + `GLM-4-Flash` |

模块化接口（推荐用新路径，旧名仅兼容）：

| 模式 | 接口 | 作用 |
|------|------|------|
| 单家具摆放 | `POST /api/room/placement-check` | 几何 + 该家具移动/中文建议；`enableAgents` |
| （兼容） | `POST /api/room/spatial-check` | **deprecated**，等价 placement-check |
| 全屋布局 | `POST /api/room/room-layout` | 场景内多家具扫描 + 全屋建议 |
| 场景深化 | `POST /api/room/scenario-advice` | `elder` / `infant` / `pet` / `fengshui`；`mode=placement\|room` |

场景没有真实点云时：请求可带完整 `scene`，或只带 `sceneId` 走 `build_mock_scene`。

样例与耗时记录：`backend/docs/spatial_modular_scenario_cases.md`、`spatial_agent_case_results.md`。  
样例输入也可参考：`sample_data/scenes/`（若本地有 `*_spatial_check.json`）。

### 建议联调顺序

1. `enableAgents=false` 先确认几何 checks 合理  
2. 再开 Agent，看 `layout.moves` / `advices`  
3. 用同一场景调 `scenario-advice`，核对场景标签是否改动建议

## 5. 功能脉络 B：离线 IKEA 视觉检索

### 设计原则

- **不依赖**京东/抖音等在线电商 API  
- **不替代** mock 的 `/api/product/recommend`；文档里写的「接到 Shopping Agent」仍是 **未做**  
- 索引与图片在 `data/product_index/`，**不进 git**

### 本机已验证规模（参考）

某次本地 meta（以你机器为准）：

- 数据集：`jeffreyszhou/ikea-us-products-2025`  
- `--sample-ratio 0.1` → 约 **2783** 条入索引  
- 模型：OpenCLIP `ViT-B-32`，权重文件 `data/product_index/ViT-B-32.pt`  
- HF 国内建议：`$env:HF_ENDPOINT='https://hf-mirror.com'`；图片实际多从 IKEA CDN 拉，HF 镜像 blob 可能 404

详细命令：`backend/docs/product_clip_offline.md`。

### 脚本流水线

```text
download_ikea_us_full.py (--sample-ratio 0.1)
  → catalog.jsonl + images/
build_index.py --pretrained data/product_index/ViT-B-32.pt
  → embeddings.npy + index.faiss + catalog_indexed.jsonl
search.py / batch_match_products.py
  → CLI 或 product_matches.json
```

批匹配默认扫 `vedios/<id>/deduplicated/*/crop.jpg`（目录名是 `vedios`，gitignore），结果写到 `outputs/videos/<id>/product_matches.json`，并会同步 crop 到 outputs 便于静态访问。

### HTTP API

| 方法 | 路径 | 说明 |
|------|------|------|
| `GET` | `/api/video/{videoId}/product-matches` | 读离线缓存；无文件则 404 |
| `POST` | `/api/video/clip-search` | **实时** CLIP；需 `.venv-retrieval` + 索引 |

`clip-search` 输入三选一：`cropUrl` | 整图 `image` | `image`+`bbox`。  
可选：`hint` / `analysis` + `imageName` → 文本融合与品类重排（`hints.py`）；`textWeight` 控制文本权重。

静态资源：

- 商品图：`/product_index/images/<id>.jpg`  
- Demo UI：  
  - `/static/pipeline-test.html` —「加载宜家商品缓存」+ 选中物体 Top3  
  - `/static/image-search.html` — 上传/选目录图搜（可带 analysis 融合）

### 效果预期（诚实边界）

- 装饰类（灯、镜、花瓶等）相对好认  
- 沙发/桌等：10% 抽样库仍可能偏「看起来像」，不是 SKU 级同款  
- 旧 Home Decor 小库（~464）更偏画框/镜，已被 US 10% 抽样替代为推荐基线

```text

from app.routers import product
app.include_router(product.router, prefix="/api/product", tags=["product"])
```

## 8. 已知坑（续）

- **`master` 无静态页** — 演示请用 `cutting`。  
- **`.venv` 可能损坏** — 勿死磕；换可用 Python 起服务。  
- **CLIP 必须 `.venv-retrieval`** — 缺则 `clip-search` 直接报错提示建环境。  
- **`data/product_index/`、`vedios/`、`.venv-retrieval/` 均 gitignore** — 换机器要重下/重建索引。  
- **并发写 catalog.jsonl** 曾出现坏行，需清洗后再 `build_index`。  
- **Windows 中文路径** — FAISS 用 serialize 读写，勿改回裸 `read_index(path)`。  
- **`/api/product` 未挂载** — 文档有案例，默认 404。  
- **空间 Agent** — key/额度/模型名不对时会静默偏 mock；用案例文档里的 live 标记对照。  
- **不要提交** `.env`、完整商品图库、大 embeddings、带密钥的 result。

## 9. 建议下一步（按收益）

1. **挂上 `/api/product`**，并明确与 CLIP 宜家结果的字段对齐（同款 vs 视觉相似）。  
2. **CLIP → recommend**：文档已写的 Vision + Top20 + Shopping Agent → Top3。  
3. **扩大/精修索引**：家具类加权抽样；或按 label 分库，减少沙发命中画框。  
4. **空间**：真实户型接入替换 mock `scan`；Agent 超时/降级策略产品化。  
5. **工程**：`clip-search` 现为同步子进程，首次加载模型慢，可常驻 worker 或缓存模型。  
6. **合并策略**：`cutting` → 主分支前清理误入的 `.venv` 历史、确认敏感与大文件未入库。
