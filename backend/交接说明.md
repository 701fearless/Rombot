# Rombot 交接说明（功能脉络 + 接口）

面向：拿到本仓库后需要快速跑通、定位瓶颈并继续优化的同学。  
分支建议：`feature/ark-seedream-hunyuan-pipeline`  
范围：`backend/` 为主；根目录 `room_scan_standalone/` **不在本交接主链路内**（本地调试目录，默认 gitignore）。

---

## 1. 产品在做什么

MVP 目标链路：

```text
视频/单帧图 → 家具检测打标 → 选中物体 → 分割/裁剪 → 特征 brief + 参考图 → Image-to-3D → GLB
```

当前**已验证可用**的端到端路径（单图/暂停帧）：

```text
DETECTION_PROVIDER=ark_grounding
SEGMENTATION_PROVIDER=mock          # bbox crop，可不接 SAM
MODEL3D_PROVIDER=feature_tripo      # 或 feature_hunyuan
```

内部 3D 子链（`feature_*` provider）：

```text
Ark 视觉 brief（或复用检测阶段 visualFeatures）
  → Seedream 生成约 45° 参考图
  → Tripo / Hunyuan 异步任务
  → 轮询拿 GLB，缓存到 outputs/
```

房间扫描 `POST /api/room/scan` 目前仍是 **mock 场景**，不是真实户型重建。

## 3. 功能脉络（按调用顺序）

### A. 实时 Feed（前端暂停视频 / 上传帧）

1. `POST /api/feed/detect`  
   - 若已有 `outputs/videos/<videoId>/analysis.json` → 走暂停帧匹配，**不调实时检测模型**  
   - 暂停帧匹配逻辑：前端传入暂停截图 `frameImage` + 暂停时间 `time`；后端只在该视频 analysis 的“前一帧 / 后一帧”里二选一，用 64-bit dHash 比较暂停截图与两侧帧的相似度，选择更相似的那一帧。
   - 若 dHash 距离相同，选时间更近者；若仍完全相同，选前一帧。
   - 返回的是匹配帧已有的 bbox / crop / mask / `frameImageUrl`，不会对暂停截图重新检测。
   - 否则走 `DETECTION_PROVIDER` 实时检测，写 `outputs/<frameId>/`
2. `POST /api/feed/select-object`  
   - 取物体 →（可选 SAM）分割 → `MODEL3D_PROVIDER.generate_asset`  
   - 返回 `glbUrl` + `generation`（brief / 参考图轨迹）
3. `POST /api/feed/run-pipeline` = detect + select（`objectId` 可空，默认第一个）

### B. 视频离线预分析（降低暂停时延迟）

1. `POST /api/video/preprocess` → `outputs/videos/<videoId>/analysis.json`  
2. 支持 `reuseExistingFrames=true`，直接读取 `outputs/videos/<videoId>/frames.json` 和 `frames/` 下人工筛好的帧，不再自动抽帧。
3. 之后 detect 走暂停帧匹配缓存：只比较暂停点前后两张已分析帧。

### C. 人工筛帧 + 暂停识别测试

1. 打开 `/static/frame-selector.html`，选择本地视频，例如 `2.mp4`，页面默认 `videoId=2`。
2. 在视频播放过程中暂停并保存需要参与后续识别的关键帧。
3. 保存结果写入：

```text
outputs/videos/<videoId>/frames/frame_t000012345ms.jpg
outputs/videos/<videoId>/frames.json
```

4. 再打开 `/static/pipeline-test.html`，选择同一个视频，点击“识别已有抽帧”。
5. 页面会调用 `/api/video/preprocess`，并带上：

```json
{
  "videoId": "2",
  "mode": "ark_grounding",
  "reuseExistingFrames": true
}
```

6. 预处理成功后，播放同一视频并暂停；页面截取暂停画面，调用 `/api/feed/detect`，后端用 dHash 在前后两张已分析帧中选择更相似的一张，并返回该帧打标结果。

### D. 联调入口

- UI：`http://127.0.0.1:8000/static/pipeline-test.html`  
- 人工筛帧：`http://127.0.0.1:8000/static/frame-selector.html`
- Debug：`POST /api/debug/image-pipeline`（本地路径图片 → Ark 检测 → 当前 3D provider）  
- OpenAPI：`http://127.0.0.1:8000/docs`

## 4. 接口文档（精简）

Base：`http://127.0.0.1:8000`  
静态产物：`/outputs/...`、`/sample_data/...`

### 视频输出目录约定

单个视频的预处理、识别、去重和暂停后生成产物都应留在该视频目录下，例如 `videoId=2`：

```text
outputs/videos/2/
  frames/                 # 人工筛帧或自动抽帧
  frames.json             # 帧时间点清单
  analysis.json           # 逐帧检测 + 去重结果
  objects/                # 预处理阶段每帧检测出的 crop/mask
  deduplicated/           # CLIP 去重后的候选代表图
  generated/2_000001/     # 暂停匹配到某帧后，选物生成 3D 的中间产物和 GLB
```

注意：老的单图/兜底实时检测可能使用 `outputs/<frameId>/`；视频预处理帧 ID 形如 `<videoId>_000001` 时，后续生成目录应映射到 `outputs/videos/<videoId>/generated/<frameId>/`。

### `GET /health`

存活检查。

### `POST /api/feed/detect`

暂停视频时，前端应传当前暂停截图到 `frameImage`。如果该 `videoId` 已有 `analysis.json`，后端不会重新检测截图，而是用截图和暂停时间在已分析帧的前后两帧里做 dHash 相似度二选一。

**Request**

```json
{
  "videoId": "living_room_001",
  "time": 12.4,
  "frameImage": "data:image/jpeg;base64,..."
}
```

**Response（节选）**

```json
{
  "frameId": "frame_living_room_001_12_40",
  "frameImageUrl": "/outputs/.../frame.jpg",
  "objects": [
    {
      "id": "obj_sofa_001",
      "label": "sofa",
      "name": "沙发",
      "confidence": 0.9,
      "bbox": [x1, y1, x2, y2],
      "tagPosition": [0.5, 0.4],
      "cropUrl": "/outputs/.../crop.png",
      "maskUrl": "/outputs/.../mask.png",
      "visualFeatures": {},
      "generationHints": {}
    }
  ]
}
```

`visualFeatures` / `generationHints`：Ark 检测阶段可写入，供后续 3D brief 复用（避免二次视觉调用）。

### `POST /api/feed/select-object`

**Request**

```json
{
  "frameId": "frame_...",
  "objectId": "obj_sofa_001",
  "frameImage": "data:image/jpeg;base64,...",
  "imageUrl": null,
  "cropImage": null
}
```

优先级：`imageUrl` → `cropImage` → 分割 crop → 检测 crop。

**Response（节选）**

```json
{
  "taskId": "...",
  "status": "success",
  "object": {
    "id": "obj_sofa_001",
    "label": "sofa",
    "name": "沙发",
    "bbox": [x1, y1, x2, y2],
    "cropUrl": "...",
    "maskUrl": "...",
    "glbUrl": "/outputs/.../model.glb"
  },
  "analysis": {
    "summary": "...",
    "placementAdvice": "..."
  },
  "generation": {
    "briefUrl": "/outputs/.../FurnitureGenerationBrief.json",
    "referenceImages": [],
    "textureReferences": [],
    "provider": "feature_tripo",
    "notes": []
  }
}
```

### `POST /api/feed/run-pipeline`

```json
{
  "videoId": "living_room_001",
  "time": 12.4,
  "frameImage": "data:image/jpeg;base64,...",
  "objectId": null
}
```

返回 `{ "detection": DetectResponse, "selected": SelectObjectResponse }`。

### `POST /api/video/preprocess`

```json
{
  "videoId": "living_room_001",
  "videoUrl": "/sample_data/videos/living_room_001.mp4",
  "sampleIntervalSec": 1.0,
  "mode": "ark_grounding",
  "maxFrames": 6,
  "reuseExistingFrames": false
}
```

`mode`：`mock` | `ark_grounding` | `grounded_sam2` | `doubao_grounding_sam` | `manual`

`reuseExistingFrames=true` 时忽略 `videoUrl` / 自动抽帧，直接读取 `outputs/videos/<videoId>/frames.json` 中的人工帧。

### `GET /api/video/analysis/{videoId}`

整份 `analysis.json`。

### `GET /api/video/analysis/{videoId}/nearest?time=12.4`

最近采样帧。

### `GET /api/video/detect/{videoId}?time=12.4`

从 analysis 直接构造 `DetectResponse`（不写盘）。

### `POST /api/room/scan`

```json
{ "scanId": "demo_living_room" }
```

返回 mock `SceneResponse`（房间尺寸 + 物体位姿 + 建议文案）。

### `POST /api/debug/image-pipeline`

```json
{
  "imagePath": "/sample_data/videos/sample.png",
  "objectIndex": 0
}
```

## 5. Provider 开关（优化前先对齐配置）

复制 `backend/.env.example` → `backend/.env`，填 key。

| 变量 | 常用值 | 说明 |
|------|--------|------|
| `DETECTION_PROVIDER` | `ark_grounding` / `mock` / `grounded_sam2` | 实时检测 |
| `SEGMENTATION_PROVIDER` | `mock` / `sam3` | mock=bbox；sam3 失败会回退 bbox |
| `MODEL3D_PROVIDER` | `feature_tripo` / `feature_hunyuan` / `mock` | **主优化对象** |
| `ARK_VISION_MODEL` | `doubao-seed-2-1-pro-260628` | 检测 + brief |
| `ARK_IMAGE_MODEL` | `doubao-seedream-5-0-lite-260128` | 参考图 |
| `ARK_IMAGE_SIZE` | `2048x2048` | Seedream 尺寸 |
| `TRIPO_*` | 见 `.env.example` | Turbo；`EXPORT_UV=false` 偏速度 |
| `HUNYUAN_MODEL` | `hy-3d-express` 或 `hy-3d-3.0` | express≠专业版字段；`LowPoly` 仅专业版 |
| `HUNYUAN_POLL_ATTEMPTS` | `120` | 单任务可达 ~10min，轮询要够 |

工厂逻辑集中在 `app/routers/feed.py` 的 `get_*_provider()`。

## 7. 建议优化切入点（按收益）

1. **时延**：`feature_*` 串行 brief → Seedream → 3D 轮询；可并行多物体、缓存 brief、跳过已有 `visualFeatures` 的二次视觉、缩短 Seedream 尺寸、调低轮询间隔/改 webhook。  
2. **质量**：prompt / negativePrompt 在 `feature_hunyuan_provider.py`（及基类 `feature_meshy_provider.py`）；主体隔离、遮挡补全、对称先验已写在 brief 规则里，可按品类分策略。  
3. **分割**：当前默认 mock bbox；接 `sam3` 或检测侧 mask 可减背景干扰（失败已有回退）。  
4. **检测稳定性**：Ark 坐标空间为 1000×1000 再转像素；标签中英映射与过滤策略在 detection / ark_grounding 相关文件。  
5. **房间级**：`/api/room/scan` 仍是 mock；真实户型/布局需另接扫描管线（勿与 `room_scan_standalone` 混为已上线能力）。  
6. **工程**：`select-object` 同步阻塞到 GLB 完成，前端体验差；可拆「提交任务 / 查进度」异步 API。  
7. **成本**：Hunyuan 有免费额度/计费差异；Tripo 与 Hunyuan 可按质量-成本做路由。

## 8. 已知坑

- **不要提交** `.env`、带签名云 URL 的 result JSON、大 GLB。  
- `hy-3d-3.1` **不支持** `LowPoly`；专业低模用 `hy-3d-3.0` + `HUNYUAN_GENERATE_TYPE=LowPoly`。  
- `hy-3d-express` **不要**传 `generate_type` / `face_count`（代码按模型分支处理，改 payload 时小心）。  
- 多视图提交若报错，Hunyuan 路径可能回退单图。  
- `room_scan_standalone` 非主仓库交付物；主路径以 `backend` API + provider 为准。
