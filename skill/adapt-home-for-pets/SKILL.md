# 住宅适宠化分析

根据真实宠物资料分析住宅，不把“宠物友好”简化成放一个窝。先处理高后果风险和逃逸，再改善休息、活动、食水、排泄、清洁、多宠关系与家具耐用性。默认采用低成本、可逆调整；购买、安装和大型家具移动只生成待确认方案。

## 不可违反的规则

1. 不把猫、狗、兔、鸟或其他物种混用同一套假设。
2. 不根据品种刻板推断行为；优先使用用户提供的抓挠、啃咬、攀爬、跳跃、挖掘、标记和逃逸记录。
3. 不声称植物、材料、清洁剂、家具或空间“对宠物安全”，除非有可追溯且适用于该物种的 JSON 证据。
4. 不把未知耐抓、耐咬、可洗、防滑、无毒、承重和稳定性写成肯定事实。
5. 不自动修改门窗、阳台、护栏、墙体、电路、燃气、厨卫或建筑结构。
6. 防逃网、窗限位、门栏、墙面固定等只记录为 `proposedSafetyInstallation`，不假装已实施。
7. 不自动大幅移动大型家具；明确高风险无法轻量解决时才提出待确认重排。
8. 不提供诊断、用药、食谱或治疗方案；健康和异常行为转介兽医或合格行为专业人员。
9. 不用精油、香薰、驱避剂、刺激性气味或不明植物作为默认“化解”。
10. 人的疏散、消防、无障碍、卫生与宠物福利同时满足，不能互相牺牲。

## 标准工作流

### 1. 读取并保全输入

用结构化解析器读取住宅 JSON，保留未知字段、原 ID、坐标、单位和精度。读取或建立 `petProfile`：

- 物种、数量、年龄、体重和体型；
- 行动能力、跳跃高度、攀爬、楼梯能力和关节/视听限制；
- 抓挠、啃咬、挖掘、吞食异物、撞门、开门、标记和逃逸行为；
- 睡眠、躲藏、活动、社交与独处需求；
- 食物、水、药物、排泄和清洁流程；
- 多宠冲突、资源守护、儿童/访客共处；
- 过敏、兽医限制和照护者约束。

缺物种时不能做商品适配；先给通用风险审计并询问物种。缺行为资料时把相关判断标为 `unknown`。

### 2. 确定完整度

- `profile-missing`: 缺物种或数量；
- `layout-relational`: 只有房间和相对关系，不改坐标；
- `geometry-partial`: 缺尺寸、门窗开启区或家具占地；
- `geometry-complete`: 可做边界、碰撞和局部通行；
- `catalog-ready`: 商品目录有物种匹配候选和足够属性。

缺商品尺寸时只能推荐，不能生成摆放坐标。缺物种适用字段时必须列为核验项。

### 3. 做物理与紧急风险审计

先运行：

```powershell
python scripts/validate_layout.py <layout.json> --pretty
```

再按顺序检查：

1. 家具越界、碰撞、堵门、人的疏散和宠物逃逸路线；
2. 开放门窗、阳台、纱窗、栏杆、楼梯和高处坠落；
3. 电线、充电器、插座、加热设备、水电组合和啃咬；
4. 有毒植物、药品、清洁剂、人食、垃圾、小物、线绳和可吞食零件；
5. 炉灶、热液、取暖器、风扇、洗衣机、烘干机和折叠机构；
6. 高柜、电视、落地灯、猫爬架、鱼缸等倾倒或承重；
7. 湿滑地面、老年/术后宠物的台阶和跳跃；
8. 食水区、排泄区、睡眠区和人的备餐区是否交叉污染；
9. 多宠之间是否有足够的分散资源、退路和躲藏空间；
10. 家具面料、边角和结构是否诱发抓咬或容易积毛、积液、藏污。

发现立即风险时先建议隔离、停用或限制访问，不等待完整装修方案。

### 4. 按物种和个体调整

- 猫：垂直移动、窗台阳台、纱窗强度、抓挠点、躲藏、猫砂、食水分离和高处承重；
- 狗：地面防滑、门口逃逸、休息边界、啃咬、食水清洁、体型通道和老年坡度；
- 兔与小型哺乳动物：电线啃咬、缝隙逃逸、有毒植物、围栏、垫材、挖掘和安静躲藏；
- 鸟：门窗与风扇、厨房烟气、线缆、笼架稳定、飞行路线和材料安全；
- 水族/爬宠：承重、水电、温控、逃逸和设备检修；具体饲养参数转介专业资料。

同物种也要按年龄、体型、疾病限制和已知行为修正。老年或行动受限宠物优先防滑、低落差和易达资源。

### 5. 分区分析

按入口/玄关、全屋通道、客厅、休息躲藏区、活动区、食水区、排泄区、厨房、卫生间、阳台窗边、储物清洁区顺序分析。

每项记录：

- `priority`: `P0 immediate`、`P1 high`、`P2 medium`、`P3 convenience`；
- `status`: `observed`、`inferred`、`unknown`；
- `confidence`: 0 到 1；
- `speciesRefs` 和 `evidenceRefs`；
- `exposure`: 可达性、频率和无人时段；
- `consequence`: 普通风险描述，不做医学断言；
- `falsifiers`: 现场信息如何改变判断。

### 6. 按最小充分动作生成建议

依次尝试：

1. `isolate`: 隔离有毒、易吞、热、电和逃逸风险；
2. `clear`: 收线、清小物、封垃圾和清洁用品；
3. `secure`: 固定、门锁、窗限位、防滑和防倾倒；
4. `redirect-behavior`: 在既有抓咬目标附近提供合法替代与奖励路径；
5. `protect`: 可洗罩、防抓垫、防水垫、墙角保护和托盘；
6. `zone`: 分开食水、排泄、睡眠、活动和人类备餐；
7. `relocate-small`: 微移小件与资源，保留人的通道和宠物退路；
8. `replace-or-buy`: 推荐目录商品；
9. `major-furniture`: 仅为明确高风险生成待确认重排。

默认输出 4-8 条建议。不要用惩罚、惊吓、刺激性气味或阻断全部自然行为保护家具；提供可接受替代目标。

### 7. 推荐家具数据库中的 1-2 件

定位用户指定、`meta.furnitureCatalogPath` 或默认目录。

运行：

```powershell
python scripts/recommend_furniture.py <catalog.json> --domain pet --species <物种> --need <问题> --max-items 2 --pretty
```

要求：

- 有候选时推荐 1-2 件，物种字段不匹配的商品必须排除；
- 两件尽量覆盖不同需求，例如休息/躲藏与清洁/收纳，或抓挠替代与防滑；
- 根据实际行为核验耐抓、耐咬、稳定、承重、可洗、防滑和材料声明；
- 只有 JSON 明确支持时才能声称对应性能；
- 目录为空时写 `catalog_empty`，不虚构宠物窝、猫爬架或品牌；
- 推荐状态为 `proposed-unpurchased`，不直接加入现有家具。

尺寸完整时可生成未应用摆放预览；还要核验退路、食水/排泄分离、窗边坠落、倾倒和人的通道。

### 8. 选择 JSON 变更

- `applied`: 轻量、可逆且物理验证通过；
- `recommended`: 缺尺寸、行为或现场信息；
- `proposedSafetyInstallation`: 防逃、固定、限位等待实施措施；
- `proposedMajorFurniturePlan`: 大型家具重排，待确认；
- `catalogFurnitureRecommendations`: 未购买商品；
- `rejected`: 产生新风险、物种不匹配或证据不足。

不把推荐商品写成现有资产，不把安装建议写成已安装，不为了宠物用品堵塞人的疏散。

### 9. 回写并验证

在顶层新增或更新 `petAdaptationAnalysis`，生成 RFC 6902 风格 `jsonPatch`。回写后检查 JSON、ID、引用、单位、边界、碰撞、门窗、通道、逃逸点、资源分区、商品证据和新增风险。失败候选撤销并降级。

## 输出顺序

1. `适宠化概况`：物种、个体特征、完整度与最高风险；
2. `立即处理`：P0/P1；
3. `分区轻量调整`：安全、福利、清洁、便捷和家具保护；
4. `家具数据库推荐`：1-2 件或目录状态；
5. `待确认安装/家具重排`；
6. `JSON 变更摘要与更新文件`；
7. `验证与复查`：新宠、年龄、行为、健康、搬家或换家具时重审。

## 工具失败

脚本或几何校验失败时只给保守文字建议，不自动改坐标，不声称商品适配或安全。列出缺失数据和现场核验项。
