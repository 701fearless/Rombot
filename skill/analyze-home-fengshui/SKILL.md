# 住宅风水轻量布局分析

把风水作为住宅环境、动线、使用感受和传统象征的辅助分析框架。先保证真实空间可用，再考虑传统解释；默认只实施低成本、可逆的小调整。

## 不可违反的边界

1. 始终把建筑边界、墙、柱、梁、门窗、楼梯、厨卫位置、上下水、燃气、电路和固定设备视为不可改动。
2. 永远不建议拆墙、砌墙、改门、封窗、迁移厨卫、改管线、开洞、吊顶遮梁或其他硬装结构工程。
3. 将“大改”严格定义为大幅搬动、旋转或重排多件现有家具。只在问题明确、证据充分、影响显著且轻量措施不能缓解时提出。
4. 不自动实施家具大改。把它写入 `proposedMajorFurniturePlan`，等待用户明确确认后再回写家具坐标。
5. 不算命，不读取或推断八字，不依据性别、出生日期预测吉凶，不声称保证财富、健康、婚姻、学业或灾祸。
6. 不使用恐吓性词语。把“煞”翻译为可观察的直冲、暴露、拥堵、眩光、尖角、噪声或失衡。
7. 安全、法律、消防、无障碍、人体工学、通风采光和用户明确需求优先于任何风水规则。

## 标准工作流

### 1. 读取并保全原始输入

使用结构化 JSON 解析器读取文件，禁止用正则或字符串替换修改 JSON。保留未知字段、原有 ID、坐标系、精度和用户元数据。

记录输入文件、时间戳、时区、单位、坐标原点、北向角、角度方向、外边界、房间、门窗、固定设施、家具占地、朝向、可移动性，以及儿童、宠物、无障碍、租房和预算等约束。

如果 JSON 无法解析，停止布局修改并报告精确错误位置。不要猜测修复会改变语义的字段。

### 2. 规范化而不臆造

将输入映射到 `json-contract.md` 的内部模型。允许原始字段名不同，但要在分析元数据中记录映射。

遵守缺失数据规则：

- 缺单位：可以分析关系，不能计算距离或自动落位实体。
- 缺房间边界或家具占地：可以给文字建议，不能移动或新增落地物件。
- 缺北向：只做形势、动线和家具关系分析，不给具体东南西北落位。
- 缺门窗尺寸或开启范围：不在门窗附近自动新增实体。
- 缺家具可移动性：默认 `unknown`，只允许建议，不自动移动。
- 缺时间戳：使用系统当前时间和项目时区，并明确记录来源。
- 缺失信息不影响安全的小建议可以继续输出；只有阻止安全落位时才提问，最多三个高价值问题。

### 3. 先做物理与安全审计

在风水分析之前检查：

1. 实体是否位于所属房间或允许区域内；
2. 家具是否穿墙、越界、互相重叠或覆盖固定设施；
3. 门扇、抽屉、柜门、窗扇和设备检修区是否可开启；
4. 主入口、房门、床边、座位和常用路线是否可通行；
5. 出口、消防设施、通风口、采光窗和无障碍区域是否被阻挡；
6. 水、火、电、热源、悬挂重物、儿童和宠物相关风险是否存在；
7. 坐卧位置是否存在明显碰头、跌倒、眩光、尖角或压迫问题。

运行：

```powershell
python scripts/validate_layout.py <layout.json> --pretty
```

把校验错误视为硬约束，不允许用风水解释覆盖。校验器无法证明的连续通行与人体工学问题仍要人工检查。

### 4. 分层分析住宅

按以下固定顺序分析：

1. 安全和物理有效性；
2. 入口、第一视线、明堂感和全屋主通道；
3. 门窗直线、长走廊、急转、拥堵和气流速度；
4. 卧室床位；
5. 书桌或工作位；
6. 沙发、餐桌和高频座位；
7. 厨房炉灶、水槽、冰箱、操作台与通风；
8. 卫生间潮湿、泄漏、气味与门口关系；
9. 光线、空气、噪声、收纳、镜面、梁、尖角与植物；
10. 数据足够时再使用罗盘方位或时间层。

对每个结论标记：

- `status`: `observed`、`inferred`、`unknown`；
- `confidence`: 0 到 1；
- `method`: `physical`、`form`、`compass`、`timing` 或 `symbolic`；
- `evidenceRefs`: 指向 JSON 路径；
- `falsifiers`: 哪些缺失信息或现场情况会推翻结论。

### 5. 给问题分级

- `P0 safety`: 现实安全或物理错误。先修复数据或现实风险，不包装成风水建议。
- `P1 strong`: 明显影响睡眠、工作、通行或长期舒适，且传统形势判断也一致。
- `P2 moderate`: 存在可观察的不适或失衡，适合轻量调整。
- `P3 optional`: 纯偏好、装饰或低置信度象征建议，可忽略。

只有同时满足以下条件，才允许提出家具大改：

1. 属于 `P1 strong`，不是纯象征性问题；
2. 至少有两个独立证据，例如门线直冲加无靠，或通行冲突加睡眠位暴露；
3. `confidence >= 0.85`；
4. 清理、微移、转向、小型屏风、窗帘、地毯、灯光等轻量方案均不足；
5. 新方案通过完整物理校验；
6. 仅涉及家具，不触碰结构、硬装、厨卫或管线；
7. 输出为待确认方案，不自动应用。

### 6. 依照调整阶梯生成建议

从上到下选择第一种足够有效的动作，不越级：

1. `repair`: 修复泄漏、松动、眩光、电线和安全问题；
2. `clear`: 清理入口、床下、桌边、通道和积水杂物；
3. `stabilize`: 增加床头支撑、椅背、脚垫、收纳或柔和照明；
4. `redirect`: 微调家具角度或位置，使用窗帘、地毯、矮柜、植物或小屏风减缓直冲；
5. `balance`: 通过材质、色彩、成对床头空间、光线和软装做平衡；
6. `activate`: 仅在空间与时间数据可靠时新增一个小型、低风险、可撤回物件；
7. `major-furniture`: 仅生成待确认的大幅家具重排方案。

默认输出 3 到 7 条建议。优先处理能同时改善现实使用和传统形势判断的动作。不要为了覆盖每个方位而堆放物件。

### 7. 生成时间层

只有时间戳明确或可安全取得时才生成。运行：

```powershell
python scripts/derive_time_context.py --timestamp <ISO-8601> --timezone <IANA-zone> --pretty
```

时间层优先级低于空间事实。每次最多给一条时间型小调整，并要求可在数分钟内撤回、不移动主要家具、不制造水电或绊倒风险、有北向时才指定罗盘方位。只称为传统象征性辅助或季节性提示；不输出未经验证的完整八字、日柱、时柱或择日结论。

### 8. 从家具 JSON 目录推荐 1-2 件

定位用户指定、户型元数据指定或项目默认的家具目录。只依据目录 JSON 中实际存在的字段筛选，不从标题常识或模型记忆补充商品能力。

运行：

```powershell
python scripts/recommend_furniture.py <catalog.json> --domain fengshui --need <问题关键词> --max-items 2 --pretty
```

遵守以下规则：

- 有合格候选时必须给出 1 到 2 件，优先对应本次最高优先级问题；
- 推荐两件时尽量解决不同问题，例如一件改善支撑，一件改善照明或收纳；
- 每件都给出商品 ID、JSON 证据路径、推荐原因、未知属性和购买前核验项；
- 目录为空或无合格候选时不编造商品，写入 `catalog_empty` 或 `no_eligible_products`；
- 缺少尺寸时不生成坐标；尺寸完整时也只生成未应用的摆放预览；
- 推荐状态固定为 `proposed-unpurchased`，不直接加入现有家具或资产列表。

### 9. 选择可安全回写的变更

把建议分为：

- `applied`: 数据充分、动作轻量、物理可验证，立即写入布局；
- `recommended`: 建议明确，但缺少尺寸、承载、开启范围或可移动性，不改实体坐标；
- `proposedMajorFurniturePlan`: 家具大改，必须等待确认；
- `rejected`: 会造成碰撞、安全风险、结构改动或收益不足。

允许自动应用的典型变更：清理标记为杂物的小件；在给定允许范围内微移小型家具；小角度旋转可移动座椅、书桌或小柜；在已知空闲区增加地毯、小植物、台灯、软帘或桌面摆件；修改软装颜色、照明状态；给镜子增加可移除遮盖状态。

不允许自动应用：大型家具大幅移动、多件家具连锁重排、任何结构与固定设施变更、无法证明占地和安全的新增物件。

### 10. 回写并验证 JSON

保留原数据，在顶层增加或更新 `fengshuiAnalysis`。对可自动实施的小改同时更新对应实体，并生成 RFC 6902 风格 `jsonPatch`。

每次回写后：

1. 重新解析 JSON；
2. 运行 `validate_layout.py`；
3. 检查新 ID 唯一、引用存在、数值有限、单位一致；
4. 比较前后，确认没有未解释的字段丢失；
5. 任何错误都撤销候选变更，降级为 `recommended`；
6. 仅当 `validation.valid` 为真时交付更新版 JSON。

## 输出顺序

1. `空间有效性摘要`：输入完整度、物理错误和可验证范围；
2. `优先建议`：问题、依据、动作、成本/难度、可逆性、置信度和观察指标；
3. `时间型小调整`：最多一条，可省略；
4. `家具数据库推荐`：1-2 件，或明确的目录为空/无候选状态；
5. `家具大改候选`：通常为空，仅在严格门槛满足时出现；
6. `JSON 变更摘要`：已应用、仅建议、被拒绝动作；
7. `更新后的 JSON` 或已更新文件路径；
8. `验证报告`：解析、边界、碰撞、门扇、通道、商品证据和安全检查结果。

每条建议用中性逻辑：观察到什么 → 为什么值得处理 → 最小动作是什么 → JSON 改了什么 → 如何验证是否更舒服。

## 取舍原则

保留与住宅可观察体验高度相关的部分：藏风聚气解释为避免强直穿堂和过度暴露；有靠解释为稳定背部支撑与心理安全；明堂解释为入口清晰、明亮、不过度拥堵；五行作为材质、色彩和季节节奏的轻量语言。

舍弃恐吓式吉凶、昂贵法器、无依据的精确断言、把镜子或水景当万能化解、按出生信息安排家具、强行混用八宅与飞星、为纯象征问题大搬家具，以及任何结构或硬装工程。

## 工具失败时

如果脚本不可运行，仍可给文字分析，但不得声称完成几何验证，不得自动回写实体坐标。把所有布局动作降级为 `recommended`，并列出需要补齐的数据。
