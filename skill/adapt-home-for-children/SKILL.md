# 住宅适儿化分析

把儿童真实年龄、能力和行为放在设计偏好之前。先消除高后果风险，再改善照护效率、成长适配、清洁维护和家具耐用性。默认采用低成本、可逆的小调整；涉及大型家具移动、安全安装或购买时生成待确认方案。

## 不可违反的规则

1. 先处理现实安全，不用“培养习惯”替代物理防护。
2. 不根据年龄假设儿童能力；使用已提供的行动阶段、身高、攀爬、开锁和吞咽行为。
3. 不声称住宅“绝对安全”或商品“儿童安全”，除非 JSON 有明确、可追溯且适用的验证信息。
4. 不把未知的圆角、承重、栏杆间距、环保、阻燃、固定件、召回或认证状态写成肯定事实。
5. 不自动修改墙体、门窗、楼梯、栏杆、电路、燃气、厨卫或其他建筑结构。
6. 墙面固定、窗户限位、楼梯门和安全锁可以作为 `proposedSafetyInstallation`，但不自动写成已完成。
7. 不自动大幅移动床、柜、沙发和餐桌；若高优先级风险无法轻量缓解，生成待确认的家具重排方案。
8. 医疗、发育、睡眠和过敏问题只建议咨询合格专业人员，不做诊断。
9. 不为展示整洁而牺牲照护视线、逃生、通风、采光和日常可达性。

## 标准工作流

### 1. 读取并保全输入

用结构化解析器读取住宅 JSON，不用正则改 JSON。保留未知字段、原 ID、坐标、单位和精度。

同时读取或建立 `childProfile`：

- `ageMonths`；
- `mobilityStage`: `non-mobile`、`rolling`、`crawling`、`pulling-to-stand`、`walking`、`climbing`、`school-age`；
- 身高、体重（仅在产品承重或可达范围确有需要时使用）；
- 是否会翻越、推拉、开锁、吞咽小物、独立如厕；
- 睡眠、喂养、换护、游戏、学习和收纳需求；
- 过敏、行动辅助和照护者限制；
- 家中儿童数量与访客儿童情况。

缺年龄和行动阶段时，先按更保守的可移动儿童模型给临时建议，并最多询问三个会改变风险等级的问题。

### 2. 确定数据完整度

- `profile-missing`: 缺年龄/行动阶段，只能做通用审计；
- `layout-relational`: 有房间和相对位置，没有可靠几何；不改坐标；
- `geometry-partial`: 有坐标但缺尺寸、开启区或固定信息；只改状态和建议；
- `geometry-complete`: 可检查边界、碰撞和局部通道；允许轻量坐标候选；
- `catalog-ready`: 家具目录有候选且关键商品属性足够；允许推荐和摆放预览。

未知数据绝不自动补全。缺尺寸时不为新商品生成坐标。

### 3. 做物理与紧急风险审计

先运行通用布局校验：

```powershell
python scripts/validate_layout.py <layout.json> --pretty
```

再按以下顺序审计：

1. 家具越界、重叠、堵门和主通道；
2. 高柜、电视、抽屉柜和可攀爬家具的倾倒；
3. 窗户、阳台、楼梯、台阶、床边和换护台的跌落；
4. 窗帘绳、电线、背带、软帘和环形绳的勒颈；
5. 缝隙、栏杆、床栏、柜门和折叠机构的夹困；
6. 小零件、纽扣电池、磁铁、药品、清洁剂和尖锐物的误食/中毒；
7. 插座、电器、拖线板、灶具、热水和取暖设备；
8. 门扇、抽屉、尖角、玻璃、地毯卷边和湿滑面；
9. 婴儿睡眠区中的软物、绳线、热源和不适用家具；
10. 照护者能否在关键区域看到儿童并快速到达。

发现可能立即造成严重伤害的情况时，先给立即隔离/停用建议，不等待完整设计分析。

### 4. 按年龄和能力调整风险

年龄只作基线，实际能力优先：

- 非移动/翻身期：睡眠面、跌落、照护台、绳线、热源和照护可达性；
- 爬行期：地面小物、插座、电线、低柜、地毯、清洁剂和门夹；
- 扶站/学步期：倾倒、攀爬、桌角、窗户、楼梯、抽屉和灶具；
- 学龄前：开锁、搬凳攀高、阳台、厨房、浴室和自主收纳；
- 学龄期：学习人体工学、电器、运动空间、隐私和自主整理，同时保留基础防倾倒。

同一住宅有多个儿童时，按风险最高且能力最强的组合设计，例如小童的吞咽风险加大童的开锁/搬凳能力。

### 5. 分区分析

按入口与全屋通道、睡眠区、爬行/游戏区、客厅、厨房餐区、卫生间、阳台窗边、楼梯、收纳区、学习区顺序分析。

每个问题记录：

- `priority`: `P0 immediate`、`P1 high`、`P2 medium`、`P3 convenience`；
- `status`: `observed`、`inferred`、`unknown`；
- `confidence`: 0 到 1；
- `evidenceRefs`: 户型或家庭资料 JSON Pointer；
- `exposure`: 儿童是否可达、使用频率和无人看护时段；
- `consequence`: 可能后果，不夸张、不诊断；
- `falsifiers`: 哪些现场信息会改变判断。

### 6. 按最小充分动作生成建议

依次尝试：

1. `isolate`: 立即隔离或停用高风险物；
2. `clear`: 移除可达小物、绳线、杂物和绊倒源；
3. `secure`: 使用合格固定、锁扣、防滑或线缆管理；
4. `soften`: 软角、缓冲、可洗罩、地垫和防撞；
5. `relocate-small`: 微移小件或危险物到不可达区域；
6. `zone`: 建立睡眠、游戏、喂养、换护、学习和收纳分区；
7. `replace-or-buy`: 推荐目录中的更适配家具；
8. `major-furniture`: 仅为明确高风险生成待确认的大型家具重排。

默认输出 4-8 条高信号建议。每条包含立即动作、长期动作、成本/工作量、可逆性、责任人和复查触发条件。

### 7. 推荐家具数据库中的 1-2 件

定位用户指定、`meta.furnitureCatalogPath` 或默认 `backend/sample_data/furniture/catalog.json`。

运行：

```powershell
python scripts/recommend_furniture.py <catalog.json> --domain child --age-months <月龄> --need <问题> --max-items 2 --pretty
```

要求：

- 有合格商品时推荐 1-2 件，每件解决已识别问题；
- 两件尽量功能互补，例如睡眠/收纳或座椅/防护；
- 年龄适用范围不匹配、目录标注高夹困/小零件/绳线/攀爬风险或缺货时不得推荐；
- 未知圆角、倾倒测试、承重、环保、阻燃和召回状态全部列为购买前核验项；
- 仅把 `verified` 声明写成已验证；
- 目录为空时写 `catalog_empty`，不使用占位商品名称。

推荐商品的状态固定为 `proposed-unpurchased`。不得自动替换现有家具；尺寸齐全时可生成未应用的 `placementPreview`。

### 8. 选择 JSON 变更

- `applied`: 轻量、可逆、数据充分且校验通过的状态或小件位置变化；
- `recommended`: 需要现场确认或缺数据；
- `proposedSafetyInstallation`: 固定件、窗限位、门栏、锁扣等待实施安全措施；
- `proposedMajorFurniturePlan`: 大型家具移动或多件重排，待用户确认；
- `catalogFurnitureRecommendations`: 未购买商品推荐；
- `rejected`: 会堵塞通道、产生新风险或缺乏证据的候选。

不自动把购买建议加入 `furniture`、`assets` 或 `placements`。不把“建议安装”写成“已经安装”。

### 9. 回写并验证

在顶层新增或更新 `childAdaptationAnalysis`，保留原始数据。生成 RFC 6902 风格 `jsonPatch`，先 `test` ID 再修改。

回写后检查：JSON 可解析、ID 唯一、引用存在、坐标有限、单位一致、房间边界、家具碰撞、门扇与通道、关键照护路线、目录证据，以及新增措施没有转移风险。任何错误都撤销候选变更并降级为建议。

## 输出顺序

1. `适儿化概况`：儿童阶段、输入完整度和最高风险；
2. `立即处理`：P0/P1，清楚说明今天先做什么；
3. `分区轻量调整`：安全、便捷、清洁和家具保护；
4. `家具数据库推荐`：1-2 件或目录状态；
5. `待确认安装/家具重排`：通常很少；
6. `JSON 变更摘要与更新文件`；
7. `验证与复查`：何时因会爬、会走、会开锁或身高变化而重审。

## 工具失败

脚本或几何校验失败时仍可输出保守建议，但不得自动改坐标、不得声称商品适配或布局已验证。把变更降级为 `recommended`，列出需要补齐的数据。
